# План главы «Сортировка на конвейере»

Глава игры «Профессии»: бутылки едут по конвейеру, игрок раскладывает их по коробкам по типу.
Коробка, в которой собралось нужное число одинаковых бутылок, закрывается, уезжает и приносит очки.
**Типов бутылок всегда больше, чем коробок**, поэтому главное решение игрока — какие типы собирать сейчас,
а какие пропустить. Стиль — стилизованный пиксель-арт по референсам из `REF/конвейер/`.

Предлагается сделать её механикой главы 2 «Оператор линии розлива» (`id: 'bottling'` в `chapters.ts`):
сортировка — основа, а брак, который был задуман для этой главы, становится усложнением на поздних уровнях.
Если заказчик захочет отдельную профессию (упаковщик, фасовщик), меняются только тексты главы, код тот же.

## 1. Механика

### Экран (вертикальный, сверху вниз)

```
+------------------------------------------+
| HUD (React): очки, время, промахи        |
| ░░ фон цеха: балки, трубы, лампы ░░      |
|                                          |
| ==> конвейер  b  b   b  b  ==> [возврат] |
|                                          |
| [стол-буфер] (с уровня 3)                |
|                                          |
|  +----+   +----+   +----+                |
|  |b b |   |    |   |b   |  [брак] (4+)   |
|  +----+   +----+   +----+                |
+------------------------------------------+
```

- Конвейер идёт слева направо в верхней трети экрана. Бутылки появляются из-за левого края.
- Внизу 2–4 коробки на «посту упаковки». Под ними пол цеха.
- Справа в конце ленты — ящик возврата: бутылка, доехавшая до него, считается промахом.

### Правила

1. **В коробку помещается `capacity` бутылок (4), типы можно смешивать.** Наклейка показывает тип,
   пока все бутылки в коробке одного типа; у пустой и смешанной коробки наклейка пустая.
2. **Коробка закрывается, только когда полна и все бутылки в ней одного типа** — клапаны закрываются,
   коробка уезжает вниз, начисляются очки, через ~0,6 с на её место выезжает новая пустая.
   Пока место пустое, туда ничего не положить — это создаёт напряжение.
3. **Бутылки можно доставать из коробки** (перетаскиванием или тап-тапом) и перекладывать в другую.
   Полная смешанная коробка трясётся и ничего не принимает, пока из неё не достанут бутылку.
   Коробка — это и временное хранилище, и головоломка: смешал — придётся разбирать.
   Бутылка из коробки, отпущенная мимо, возвращается в свою коробку (если место заняли — в любую
   свободную, иначе в ящик возврата).
4. **Промах:** бутылка доехала до конца ленты. После `maxMisses` промахов смена сорвана (0 звёзд).
5. **Высыпать коробку:** долгое нажатие (0,6 с) на коробку — бутылки уходят в возврат, коробка снова пустая.
   Стоит очков (−50), но спасает, когда «застрял» тип, который давно не едет.
6. **Стол-буфер** (с уровня 3): 1–2 ячейки, куда можно отложить бутылку. Даёт простор для планирования.
7. **Брак** (с уровня 4): бутылка со сколом или недоливом. Её нужно перетащить в ящик брака.
   Брак в коробке — коробка «испорчена» и высыпается сама; брак, уехавший в возврат, промахом не считается.

### Управление (одним пальцем, плюс мышь и клавиатура)

- **Перетаскивание:** нажать на бутылку → она поднимается и идёт за пальцем со смещением вверх
  (чтобы палец её не закрывал) → отпустить над коробкой. Зона попадания коробки шире самой коробки.
  Отпустили мимо — бутылка возвращается на своё место на ленте.
- **Тап-тап:** тап по бутылке выделяет её (рамка), тап по коробке отправляет туда.
  Работает одновременно с перетаскиванием — кому как удобнее.
- **ПК:** клавиши `1…4` отправляют в коробку самую правую (ближайшую к концу) бутылку на ленте,
  `Q` — в буфер, `X` — в брак. Удобно и быстро, тап-кнопки не нужны.
- Минимальная зона касания бутылки — 48 CSS px по высоте, даже если сам спрайт меньше.

### Генерация бутылок

Чистый рандом даёт неприятные серии, поэтому бутылки берутся из «мешка»:

- В мешок кладётся по `capacity` бутылок каждого типа, мешок перемешивается, опустошается и наполняется снова.
  Так каждый тип гарантированно приходит в количестве, достаточном для коробки.
- На лёгких уровнях есть **подсказка генератора**: с вероятностью `assist` следующая бутылка берётся
  из типов, уже назначенных коробкам. На экзамене `assist = 0`.
- Брак и «золотая» бутылка (если будет, см. п. 9) подмешиваются поверх мешка с заданной долей.

### Очки и звёзды

| Событие | Очки |
|---|---|
| Коробка закрыта | `100 × capacity / 3` |
| Комбо: следующая коробка закрыта в течение 4 с | множитель ×1,5, ×2, ×2,5 (максимум ×3) |
| Брак убран в ящик брака | +20 |
| Высыпать коробку | −50 |

Уровень — это смена фиксированной длины (60–90 с). Звёзды по шаблону `PLAN.md`:

- **1 звезда** — смена не сорвана и набрано `stars[0]` очков (цель уровня);
- **2 звезды** — набрано `stars[1]`;
- **3 звезды** — набрано `stars[2]` и не больше одного промаха.

Если смена закончилась, а `stars[0]` не набрано — 0 звёзд. Пороги подбираются на плейтесте.

### Типы упаковок

Продукция «Очаково» по референсам `REF/напитки`. Различаются **силуэтом, цветом и логотипом** —
не только цветом (дальтонизм, мелкий экран). Порядок в `bottleTypes.ts` важен: уровень берёт первые
`types` типов, поэтому первыми идут непохожие упаковки.

| Тип | Силуэт | Цвета | Наклейка на коробке |
|---|---|---|---|
| Квас «Очаковский» | широкая банка 0,5 л | золотой, красно-коричневое «О», зелёная лента | логотип «О» |
| Cool Cola | тонкая банка 0,33 л | диагональ синий/красный | белая «C» |
| iNice | ПЭТ 0,5 л, зелёный колпачок | чай, оранжевая этикетка | плашка и лимоны |
| «Мохито» | широкая банка 0,5 л | светлая, лайм, красная надпись | долька лайма |
| Street | тонкая банка 0,33 л | диагональ жёлтый/зелёный | белая «S» |
| Квас «Очаковский» 1,5 л | большая коричневая ПЭТ | коричневый, золотая этикетка | силуэт бутылки |

Рисунок упаковки задаётся строками без контура; контур и объём (блик во втором столбце, тень
в правой четверти каждой строки) добавляются при сборке спрайта.

## 3. Визуальный стиль: стилизованный пиксель-арт

### Что берём из референсов (`REF/конвейер/`)

- **Тёмная контурная обводка** в 1 пиксель у всех объектов (не чёрная, а тёмно-синяя/графитовая).
- **Объём ступенями:** у каждого цвета 2–3 тона (свет, основной, тень), без градиентов и сглаживания.
- **Конвейер:** серо-стальная рама с закруглёнными концами, ролики-«кольца» в ряд, тёмно-синяя лента.
- **Коробки:** крафтовый картон, светлая полоса скотча, красная наклейка с «текстом» из точек,
  маленькие квадратики-значки в углу.
- **Фон цеха:** приглушённая сине-зелёная гамма, оранжевые балки, трубы, лампы-полосы под потолком,
  щиты с жёлтыми экранчиками. Фон тёмнее и менее насыщен, чем игровые объекты, чтобы они читались.
- Роботы-манипуляторы из первого референса — декор у краёв ленты (анимированы 2–3 кадрами),
  в финале можно «подавать» ими новые коробки.

### Палитра (16 цветов + цвета напитков)

```
Контур        #1b1f2e
Сталь         #e3ebf0  #b7c5cf  #7f909c  #4f5d6a
Лента         #3b4266  #2a2f4a
Картон        #d9b48a  #c49a6c  #9c7148  #6e4b2c
Наклейка      #b0303a  #f4ece0
Цех (фон)     #23363b  #2f4a4f  #3e6363  #587f7a
Балки, акцент #e0632e  #a8431d
Лампы, экраны #f4d35e  #fff3b0
```

Цвета напитков — по 3 тона на каждый, подбираются на стайлгайде главы.

### Техника

- **Логическое разрешение:** поле 150×240 «пикселей». Всё рисуется в этих координатах, на экран выводится
  с **целым** увеличением (на телефоне ×5, на ПК ×3–×4 — с учётом `dpr`). Нецелое увеличение даёт «плавающие» пиксели.
  Чтобы на телефоне шириной 360–390 px не терять четверть экрана, увеличение выбирается так, чтобы влезали
  центральные 144×236: по краям может обрезаться несколько пикселей, но там только фон. Фон цеха нарисован
  с запасом, поэтому на экранах другой пропорции по краям видно продолжение цеха, а не пустоту.
- В `PhaserGame` добавить опцию `pixelArt` (в конфиг игры `pixelArt: true` + `roundPixels`):
  фильтр NEAREST для текстур и округление координат. Остальные игры её не включают.
- **Спрайты рисуются кодом, попиксельно:** каждый спрайт — массив строк,
  каждый символ — индекс палитры (`.` — прозрачный). Помощник `pixelTexture(scene, key, rows, palette)`
  рисует его на canvas 1:1. Так спрайты остаются в коде (ноль файлов, легко менять цвета),
  а художнику или дизайнеру их удобно править.

  ```ts
  const KVAS = [
    '...aa...',
    '...aa...',
    '..obbo..',
    '.obbbbo.',
    // …
  ]
  ```

- Варианты бутылок одного силуэта получаются подменой палитры, а не новыми спрайтами.
- **Анимация — по кадрам, не плавно:** лента — 4 кадра сдвига полос, ролики — 2 кадра, мигание ламп,
  клапаны коробки — 3 кадра закрытия, «пуф» из квадратных пикселей при закрытии и промахе.
  Позиции объектов всегда целые.
- **Текст «+150»** в мире — пиксельный шрифт из спрайта цифр (8 символов хватит).
- **HUD и меню (React)** — общие для игры «Профессии». Внутри главы можно добавить пиксельный шрифт
  с кириллицей (например, Pixelify Sans или Press Start 2P), **подключённый локально**, а не с CDN —
  в Telegram и без сети он должен работать. Решить на стайлгайде, не разойдётся ли это со стилем оболочки.

## 4. Архитектура

```
src/career/chapters/bottling/
  BottlingLevels.tsx  компонент LevelProps: PhaserGame + HUD главы, пауза, подсчёт звёзд
  BottlingScene.ts    сцена: лента, бутылки, коробки, ввод, правила
  levels.ts           параметры уровней (таблица из п. 2)
  config.ts           общие числа: размеры, очки, тайминги анимаций
  bottleTypes.ts      типы упаковок: рисунок, палитра, наклейка
  pixel.ts            pixelTexture(), палитра, пиксельные цифры
  sprites.ts          сами спрайты: бутылки, коробка, лента, фон, декор
  spawner.ts          «мешок» бутылок с подсказкой генератора (чистая логика, без Phaser)
  bottling.css
```

- В `chapters.ts` у главы `bottling`: `component: lazy(() => import('./chapters/bottling/BottlingLevels'))`,
  новые `mechanic`, `levels`, при необходимости `intro`.
- **Связка React ↔ Phaser:** сцена получает `bridge` с `onHud({ score, timeLeft, misses, combo })`,
  `onEnd({ score, misses, failed })` и `onReady(scene)`. Звёзды считает React-компонент по `levels.ts`
  и вызывает `onFinish(stars)`. Проп `paused` → `scene.scene.pause()/resume()`.
- `levelIndex` передаётся в сцену при старте; «Заново» в оболочке перемонтирует компонент — отдельный
  `restartGame()` не нужен.
- **Состояние сцены — простые структуры данных** (массив бутылок на ленте, массив коробок `{ type, count }`),
  спрайты только отображают их. Правила (`canPut`, `put`, `closeBox`) — чистые функции, их легко проверить вручную.
- Звук — `shared/sfx.ts` (звон при укладке, аккорд при закрытии коробки, глухой удар при отскоке и промахе),
  вибрация — `platform.haptic`: `select` при взятии бутылки, `tap` при укладке, `success` при закрытии,
  `error` при промахе.
- Обучение уровня 1 — React-слой поверх сцены (палец-подсказка, короткие фразы наставника Марины),
  сцена сообщает о событиях через `bridge` («первая бутылка в коробке», «первая коробка закрыта»).

## 5. Этапы

| Этап | Что делаем | Результат | Ориентир |
|---|---|---|---|
| **1. Серый прототип** | Сцена с прямоугольниками вместо спрайтов: лента, мешок, перетаскивание и тап-тап, коробки, закрытие, промахи, очки. Один уровень, числа в `config.ts` | Механика проверена на телефоне и в Telegram: удобно ли пальцем, хватает ли времени | 3–4 дня |
| **2. Пиксельный каркас** | `pixelArt` в `PhaserGame`, целочисленное масштабирование, `pixel.ts`, палитра. Один эталонный спрайт каждого вида: бутылка, коробка, кусок ленты, фон | Стайлгайд главы, согласованный с заказчиком | 3–4 дня |
| **3. Все уровни** | `levels.ts`, буфер, брак, высыпание, ускорение, комбо, звёзды, подключение к оболочке через `LevelProps` | Глава проходится от начала до экзамена (графика ещё частично серая) | 4–5 дней |
| **4. Графика и анимации** | Все типы бутылок, кадры ленты и коробок, фон цеха, роботы-декор, частицы, цифры очков | Глава в финальном виде | 4–5 дней |
| **5. Обучение и звук** | Подсказки уровня 1, реплики наставника, звуки, вибрация, клавиши на ПК | Новичок понимает правила без текста-инструкции | 2–3 дня |
| **6. Баланс и плейтест** | 5–10 человек, телефон и Telegram; подбор скорости, интервалов, порогов звёзд | Финальные числа в `levels.ts` | 3–4 дня |

Итого около 4 недель на одного разработчика, что совпадает с оценкой «2–3 нед. на главу» в `PLAN.md`
плюс время на пиксельный стайлгайд, который потом пригодится другим главам.

## 6. Проверка

- `npm run build` и `npm run lint` без ошибок.
- `?app&unlock` — прохождение всех уровней главы; пауза кнопкой, «назад» и сворачиванием останавливает ленту.
- Телефон (Android и iPhone) и Telegram: перетаскивание не вызывает свайп-закрытие и прокрутку,
  бутылку видно из-под пальца, нет «мыла» на пикселях при любом `dpr`, 60 FPS на слабом Android.
- ПК: мышь и клавиши `1…4`, `Q`, `X`.
- Крайние случаи: отпустить бутылку в момент, когда коробка уезжает; две бутылки в коробку одновременно
  (мультитач); пауза во время перетаскивания (бутылка возвращается на ленту); последняя секунда смены.

## 7. Риски

| Риск | Что делать |
|---|---|
| Бутылки слишком мелкие для пальца при ширине поля 180 px | Зона касания больше спрайта, проверить в прототипе; при нужде — поле 160 px |
| Игрок «застревает» с неподходящими типами в коробках | Мешок с гарантией количества, `assist`, высыпание коробки |
| Типы плохо различаются на маленьком экране | Силуэт + логотип + цвет, проверка в оттенках серого |
| Пиксельный стиль спорит с плоским стилем оболочки и других глав | Решить на стайлгайде: пиксель только в игровом мире или во всей игре |
| Нецелое масштабирование на нестандартных экранах | Только целый множитель, остаток — поля фона |
