# План разработки MVP «Очаково Games»

Цель: публичный MVP — лендинг, 3–4 режима игры (сайт + Telegram Mini App), аналитика, выкладка на сервер в РФ, домен.

## Текущее состояние

- Лендинг готов; форма заявки ничего не отправляет (`Landing.tsx`, `onSubmit` только делает `setSent(true)`).
- Готова одна глава игры «Профессии» — `bottling` («Сортировка на конвейере»). Остальные 5 глав идут через `StubLevel`.
- «Бутылочный рейс» и скрипты туннелей удалены. В `games/registry.ts` только «Профессии».
- Шрифты подключены локально (`@fontsource-variable/*`), внешних запросов к Google Fonts нет.
- Аналитики нет. Бэкенда нет: статическая сборка Vite (`base: './'`).
- Git отключён (папка `.git` удалена), автодеплой через GitHub Actions недоступен.

## Этап 0. Фундамент (1–2 дня)

1. ~~Self-host шрифтов~~ — сделано.
2. Купить домен `.ru`/`.рф` и хостинг (на старте Timeweb Cloud Apps или Beget; VPS, если понадобится бэкенд). Делает пользователь.
3. Первая выкладка «как есть» (статический `dist/`).
4. Подключить Mini App в @BotFather: `/newbot`, `/newapp`, URL вида `https://домен/?app`. Подробности — `docs/TELEGRAM.md`.

Хостинг: Timeweb Cloud Apps, Beget, Selectel, Yandex Cloud, VK Cloud, VPS + nginx. GitHub Pages и Cloudflare Pages в РФ нестабильны. Для Telegram нужен постоянный HTTPS.

## Этап 1. Аналитика (2–3 дня) — до новых игр

1. `track(event, props)` в интерфейсе `Platform` (`src/platform/types.ts`), реализации в `web.ts` и `telegram.ts`. Общие поля: `platform`, `userId` (анонимный id; в Telegram — `platform.user`), `startParam`, `sessionId`.
2. Отправка: Яндекс.Метрика для MVP; позже батч через `sendBeacon` на собственный эндпоинт на VPS.
3. События:
   - `app_open`, `landing_play_click`;
   - `lead_submit` (форма в `Landing.tsx`, около стр. 157);
   - `game_start` / `game_over` / `game_exit`;
   - `level_start` / `level_finish` / `pause` (`career/screens/LevelScreen.tsx`, около стр. 97);
   - `chapter_unlock` (`career/progress.ts`).
4. Согласие на cookie и политика конфиденциальности (152-ФЗ).

## Этап 2. Форма заявки (1 день, можно параллельно с этапом 1)

Реальная отправка заявок: Telegram-бот или почта через серверный эндпоинт либо сервис форм. Без этого заявки теряются.

## Этап 3. Режимы игры (2–4 недели)

По возрастанию трудозатрат:

1. **Сортировка на конвейере** — глава `bottling`, готова.
2. **Водитель** — глава `driver` («Доставка по городу на время»). Механику нужно делать с нуля, прежняя основа удалена.
3. **Ещё одна глава** на выбор из `warehouse` / `lab` / `technologist` (см. `docs/PLAN.md`).
4. Четвёртый режим — по результатам аналитики.

Состав режимов нужно пересмотреть: после удаления «Бутылочного рейса» готов только один. Для MVP достаточно трёх.

Для каждого: компонент с `LevelProps` (поле `component` в `chapters.ts`) или запись в `games/registry.ts`; проверка в `?app` и на телефоне/в Telegram.

## Этап 4. Полировка и запуск (3–5 дней)

- Баланс и звуки.
- Ссылки Telegram/VK на лендинге (сейчас заглушки `t.me/`, `vk.com/`).
- OG-теги и превью для шаринга.
- Кэш-заголовки: `index.html` no-cache, `assets/*` immutable.
- Lighthouse, прогон на реальных iOS/Android.
- Деплой: ручная загрузка `dist/` или `rsync` по SSH (автосборка в Timeweb возможна, если подключить репозиторий).

## Порядок для MVP

Этап 0 → 1 → (2 параллельно) → 3 → 4. Сначала домен, выкладка текущей версии, подключение к Telegram и аналитика — это позволяет тестировать на людях.

## Проверка

`npm run build` (проверка типов) + `npm run lint`; `npm run preview` с телефона; параметры `?app`, `?unlock`, `?debug`. На домене — открытие в Telegram (Android/iOS) и приход событий в реальном времени в Метрике.
